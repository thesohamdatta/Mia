# Your first workflow

MIA makes the path from intent to verified handoff explicit. Not every task needs every phase.

1. **Clarify — `mia grill`:** surface assumptions, risks, scope, and definition of done.
2. **Plan — `mia plan`:** make steps and success criteria explicit.
3. **Specify — `mia spec`:** use for larger changes that need a structured specification.
4. **Execute:** make focused changes in your development environment.
5. **Review — `mia review`:** run the pre-landing review workflow.
6. **Verify — `mia health`:** run repository verification checks.
7. **Handoff — `mia ship`:** check whether verification and handoff conditions are satisfied.
8. **Learn — `mia learn` / `mia retro`:** record useful lessons.

The `ship` command is a readiness gate. It does not push, merge, or open a pull request.

Use `mia --help` to confirm commands available in your version.
